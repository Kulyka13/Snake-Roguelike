# Практична робота №7
**Тема:** Проєктування структури програмного забезпечення
**Результат:** Class Diagram + опис структури

---

### 1. Основні компоненти системи та їх відповідальність

Архітектура гри побудована за модульним принципом у середовищі Unity із чітким розділенням обов'язків:
1. **Ігровий контролер персонажа (`SnakeMovement`):** головний компонент, що керує сітковим позиціонуванням, дискретним кроком за таймером, введенням (Unity New Input System), генерацією історії позицій, інтерполяцією для плавної графіки та детекцією самоколізій.
2. **Підсистема генерації та ресурсів (`Food`):** відповідає за збереження меж арени, перевірку вільних клітинок на основі зайнятих позицій змійки та випадковий респавн цільового об'єкта.
3. **Компоненти сегментів тіла (`SnakeSegment`, `PathPoint`):** структури даних та допоміжні скрипти префабів сегментів для збереження просторових точок і налаштування індивідуального інтервалу між частинами хвоста.

---

### 2. Опис основних класів та структур

* **`SnakeMovement : MonoBehaviour`**
  * *Призначення:* центральний клас ігрового циклу змійки, обробник руху та стану сесії.
  * *Ключові поля:*
    * `float gridSize`, `float stepInterval`, `float segmentSpacing` — конфігурація дискретної сітки та кроку.
    * `GameObject segmentPrefab`, `List<Transform> _segments` — керування префабами та колекцією сегментів хвоста.
    * `Food food` — посилання на об'єкт їжі на сцені.
    * `Vector2Int _gridPosition`, `_gridDirection`, `_inputDirection` — логічний вектор і поточна клітинка голови.
    * `List<Vector2Int> _positionHistory` — буфер історії координат для переміщення сегментів.
    * `bool _isDead`, `float _stepTimer` — стан сесії та таймер ігрового тіку.
  * *Основні методи:*
    * `HandleInput()` — обробка введення через New Input System із захистом від розвороту на 180°.
    * `PerformStep()` — дискретний крок сіткою, детекція зіткнень, оновлення буфера історії та поворот спрайта.
    * `CheckSelfCollision(Vector2Int targetPosition) : bool` — перевірка перетину наступного кроку голови з точками хвоста.
    * `EatFood()` / `AddSegment()` — інстанціювання нового префаба сегмента та виклик респавну їжі.
    * `SmoothVisuals()` / `GetPositionAtStepOffset(float stepOffset) : Vector3` — плавна лінійна інтерполяція (Lerp) між дискретними вузлами сітки для усунення ривків графіки.
    * `Die()` / `RestartGame()` — обробка поразки, очищення пам'яті хвоста та скидання сесії за натисканням `R`.

* **`Food : MonoBehaviour`**
  * *Призначення:* обробка розташування ресурсу та перевірка доступності комірок.
  * *Ключові поля:*
    * `Vector2Int gridPosition` — логічні координати яблука на сітці.
    * `Vector2Int minBounds`, `maxBounds` — прямокутні межі арени спавну.
    * `float _gridSize` — масштаб сітки в юнітах рушія.
  * *Основні методи:*
    * `Init(float gridSize)` — первинне задання розміру комірки.
    * `Respawn(List<Vector2Int> occupiedPositions)` — алгоритмічний пошук вільних клітинок методом виключення зайнятих точок змійки та перенесення позиції у випадкову доступну комірку.

* **`SnakeSegment : MonoBehaviour`**
  * *Призначення:* компонент, закріплений за префабом частини тіла.
  * *Поля:* `float customSpacing` — додатковий кастомний відступ сегмента.

* **`PathPoint (struct)`**
  * *Призначення:* легковагова структура даних для запису вузлових точок траєкторії.
  * *Поля:* `Vector2 Position`, `Quaternion Rotation`, `float DistanceFromLast`, `bool IsTeleport`.

---

### 3. Взаємозв'язки між класами

* **Асоціація (1 до 1):** `SnakeMovement` напряму посилається на екземпляр `Food`, передаючи йому координати зайнятих клітинок під час респавну та викликаючи перевірку збігу позицій `_gridPosition == food.gridPosition`.
* **Композиція / Агрегація (1 до багатьох):** `SnakeMovement` створює (`Instantiate`), зберігає у списку `_segments` і видаляє (`Destroy`) об'єкти сегментів із компонентом `SnakeSegment`.
* **Залежність за даними:** `Food.Respawn()` приймає колекцію точок, сформовану методом `SnakeMovement.GetOccupiedGridPositions()`, що гарантує спавн виключно на вільних ділянках карти.

### 5. Пояснення прийнятих проєктних рішень

1. **Розділення дискретної логіки та візуалізації:**
   Логічне переміщення відбувається суворо по клітинках цілочисельної сітки (`Vector2Int`) за фіксованим таймером (`stepInterval`), тоді як метод `SmoothVisuals()` виконує кадровий `Lerp` у звичайному `Update()`. Це гарантує точність математики сітки класичної змійки без втрати плавності картинки на моніторах із високою частотою оновлення.

2. **Історія позицій замість прив'язки сегментів за фізикою:**
   Використання буфера `_positionHistory` з динамічним обрізанням непотрібних кроків дозволяє реалізувати гнучке слідування сегментів один за одним без багів накладання та без використання важких фізичних з'єднань (`HingeJoint` / `Rigidbody2D`).

3. **Ізольована валідація вільного простору в `Food`:**
   Клас `Food` не шукає змійку на сцені самостійно через важкі методи на зразок `FindObjectsOfType`. Натомість `SnakeMovement` передає готовий хеш-список зайнятих точок у `Respawn()`, що виключає помилки спавну їжі всередині тіла або голови гравця.
