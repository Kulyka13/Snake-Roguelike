# Практична робота №16
**Тема:** Автоматизоване тестування  
**Мета:** Ознайомитися з принципами автоматизованого тестування та реалізувати перші автоматизовані тести.  
**Результат:** Набір автоматизованих модульних тестів (Unity Test Framework)

---

### 1. Вибір функцій для автоматизованого тестування
Для автоматизації за допомогою **Unity Test Framework (NUnit)** обрано чисту ігрову логіку та математичні обчислення, які не потребують ручного введення користувача, мають чіткі вхідні та вихідні дані й критично впливають на стабільність ігрового циклу **Snake-Roguelike**:

1. **Телепортація через межі арени (`ArenaSpawner.WrapPosition`):** перевірка коректного перенесення координат `Vector2Int` при виході за праву, ліву, верхню та нижню межі поля (позитивні сценарії виходу за межі та негативні/граничні сценарії перебування всередині арени).
2. **Визначення самоколізії змійки (`SnakeBody.CheckSelfCollision`):** перевірка зіткнення голови із сегментами власного тіла, коли довжина змійки ≥ 3 сегментів (позитивний сценарій зіткнення та негативний сценарій руху по вільній клітинці або занадто короткого хвоста).
3. **Поглинання удару щитом (`SnakeEffectsManager.TryAbsorbHit`):** перевірка скидання таймера активності (`shieldTime`) модифікатора «Броньований панцир» при отриманні шкоди та відмови в захисті, коли щит неактивний.
4. **Додавання та видалення сегментів тіла (`SnakeBody.AddSegment`, `SnakeBody.RemoveLastSegments`):** перевірка коректної зміни лічильника довжини `SegmentCount` та захисту від виходу за межі списку при спробі видалити більше сегментів, ніж є у змійки (негативний сценарій).

### 2. Реалізація набору автоматизованих тестів
У каталозі `Assets/Editor/` створено тестовий клас `SnakeLogicTests.cs`, що містить 5 модульних тестів для перевірки позитивних і негативних сценаріїв:

```csharp
using NUnit.Framework;
using UnityEngine;

public class SnakeLogicTests
{
    private GameObject _testRoot;
    private ArenaSpawner _spawner;
    private SnakeBody _snakeBody;
    private SnakeEffectsManager _effects;

    [SetUp]
    public void SetUp()
    {
        _testRoot = new GameObject("TestSnakeRoot");

        _spawner = _testRoot.AddComponent<ArenaSpawner>();
        _spawner.arenaMinBounds = new Vector2Int(-10, -5);
        _spawner.arenaMaxBounds = new Vector2Int(10, 5);

        _effects = _testRoot.AddComponent<SnakeEffectsManager>();
        _snakeBody = _testRoot.AddComponent<SnakeBody>();
        _snakeBody.segmentSpacing = 1f;

        GameObject segPrefab = new GameObject("DummySegment");
        segPrefab.transform.SetParent(_testRoot.transform);
        _snakeBody.segmentPrefab = segPrefab;
        _snakeBody.Init(1f, Vector2Int.zero, _effects);
    }

    [TearDown]
    public void TearDown()
    {
        Object.DestroyImmediate(_testRoot);
    }

    // Тест 1 (Позитивний): телепортація через протилежні межі арени
    [Test]
    public void WrapPosition_WhenOutOfBounds_WrapsToOppositeSide()
    {
        Vector2Int wrappedRight = _spawner.WrapPosition(new Vector2Int(11, 2));
        Vector2Int wrappedBottom = _spawner.WrapPosition(new Vector2Int(-3, -6));

        Assert.AreEqual(new Vector2Int(-10, 2), wrappedRight);
        Assert.AreEqual(new Vector2Int(-3, 5), wrappedBottom);
    }

    // Тест 2 (Негативний / граничний): координати всередині меж не змінюються
    [Test]
    public void WrapPosition_WhenInsideBounds_RemainsUnchanged()
    {
        Vector2Int boundaryPos = new Vector2Int(10, -5);
        Vector2Int result = _spawner.WrapPosition(boundaryPos);

        Assert.AreEqual(boundaryPos, result);
    }

    // Тест 3 (Позитивний та негативний): детекція самоколізії з хвостом
    [Test]
    public void CheckSelfCollision_DetectsTailHitOnlyWhenLongEnough()
    {
        // Додаємо 4 сегменти та формуємо траєкторію кроку
        for (int i = 0; i < 4; i++) _snakeBody.AddSegment();

        _snakeBody.RecordHeadStep(new Vector2Int(1, 0));
        _snakeBody.RecordHeadStep(new Vector2Int(2, 0));
        _snakeBody.RecordHeadStep(new Vector2Int(2, 1));
        _snakeBody.RecordHeadStep(new Vector2Int(1, 1));

        // Позитивний сценарій: клітинка зайнята сегментом тіла
        Assert.IsTrue(_snakeBody.CheckSelfCollision(new Vector2Int(0, 0)));
        // Негативний сценарій: сусідня клітинка вільна
        Assert.IsFalse(_snakeBody.CheckSelfCollision(new Vector2Int(1, 2)));
    }

    // Тест 4 (Позитивний та негативний): робота щита "Броньований панцир"
    [Test]
    public void TryAbsorbHit_ConsumesShieldTimeAndReturnsFalseWhenInactive()
    {
        _effects.shieldTime = 5f;

        bool firstHitAbsorbed = _effects.TryAbsorbHit();
        bool secondHitAbsorbed = _effects.TryAbsorbHit();

        Assert.IsTrue(firstHitAbsorbed);
        Assert.AreEqual(0f, _effects.shieldTime);
        Assert.IsFalse(_effects.HasShield);
        Assert.IsFalse(secondHitAbsorbed);
    }

    // Тест 5 (Негативний): безпечне видалення більшої кількості сегментів, ніж існує
    [Test]
    public void RemoveLastSegments_WhenCountExceedsLength_ClampsToZeroWithoutException()
    {
        _snakeBody.AddSegment();
        _snakeBody.AddSegment();

        Assert.DoesNotThrow(() => _snakeBody.RemoveLastSegments(5));
        Assert.AreEqual(0, _snakeBody.SegmentCount);
    }
}
```

### 3. Запуск тестів, аналіз результатів та виправлення виявлених помилок

1. **Запуск тестування:**
   * Відкрито вікно **Window → General → Test Runner** у середовищі Unity, обрано вкладку **EditMode** та запущено всі тести через **Run All**.
2. **Аналіз результатів та виправлення виявлених помилок:**
   * Під час першого прогону тест `RemoveLastSegments_WhenCountExceedsLength_ClampsToZeroWithoutException` завершився з помилкою (`Failed`), оскільки метод `SpriteFadeOut.StartFade()` використовував стандартний `Destroy()`, який не дозволений поза ігровим циклом (`Destroy may not be called from edit mode! Use DestroyImmediate instead`).
   * *Виправлення:* у `SpriteFadeOut.StartFade()` додано перевірку `if (!Application.isPlaying)` із використанням `DestroyImmediate()`, що забезпечило коректне очищення об'єктів як під час гри (`Play Mode`), так і під час модульного тестування (`Edit Mode`).
3. **Повторний прогін:**
   * Після внесення виправлення виконано повторний запуск у **Test Runner** — усі 5 тестів завершилися зі статусом **Passed** (час виконання ~0.05 с).

### 4. Висновок
У ході практичної роботи опановано принципи модульного автоматизованого тестування за допомогою **Unity Test Framework**. Визначено критичні функції ігрової логіки (`WrapPosition`, `CheckSelfCollision`, `TryAbsorbHit`, `RemoveLastSegments`), реалізовано набір із 5 автоматизованих тестів для перевірки позитивних і негативних сценаріїв, виявлено та усунуто проблему знищення об'єктів у `EditMode`, після чого підтверджено успішне проходження всіх перевірок.
