# Практична робота №12
**Тема:** Планування розробки та створення MVP
**Результат:** MVP + план реалізації першої ітерації

---

### 1. Аналіз Backlog та визначення меж MVP

**MVP (Minimum Viable Product)** для проєкту **Snake-Roguelike** — це перша робоча версія гри, яка об'єднує базовий ігровий цикл змійки (рух по сітці, поглинання їжі, ріст хвоста, обробка поразки та перезапуск) і повноцінну систему вибору та застосування roguelite-модифікаторів, що формують унікальність геймплею.

#### Розподіл функціональності з Backlog:

| Категорія | Функціональність | Статус для MVP | Обґрунтування |
| :--- | :--- | :---: | :--- |
| **Обов'язкові функції (Must Have — входять у MVP)** | Дискретний сітковий рух змійки (`SnakeMovement`) | Включено | Базова механіка керування персонажем |
| | Спавн об'єктів на вільних клітинках (`Food`, `ArenaSpawner`) | Включено | Основна ціль гравця в межах забігу |
| | Нарощування та слідування сегментів хвоста (`SnakeBody`, `SnakeSegment`) | Включено | Ключове ускладнення геймплею |
| | Детекція зіткнень (зі стінами / межами та власним тілом) | Включено | Умова програшу та завершення забігу |
| | Підрахунок поточного рахунку та швидкий перезапуск забігу | Включено | Забезпечує безперервний ігровий цикл |
| | Система roguelite-модифікаторів (`MutagenFood`, `ModifierSelectionUI`, `SnakeEffectsManager`) | Включено | Ключова фіча проєкту, що відрізняє його від класичної змійки |
| **Додаткові функції (Post-MVP — наступні ітерації)** | Збереження глобальних рекордів (`High Score`) та таблиця статистики між сесіями | Відкладено | Не блокує тестування основного геймплею та модифікаторів |
| | Плавні візуальні переходи, додаткові типи яблук і порталів (`PortalApplePair`, `SpriteFadeIn/Out`) | Відкладено | Розширюють варіативність та візуальне полірування |
| | Повноцінне меню паузи, налаштування звуку та екран налаштувань | Відкладено | Допоміжний функціонал релізної версії |

### 2. Декомпозиція User Stories на технічні задачі

Для реалізації MVP обрано ключові користувацькі історії з беклогу та розбито їх на атомарні задачі розробки:

* **US-01: Керування змійкою на ігровому полі**
  * *Task 1.1:* Налаштувати сцену `SampleScene` та тайлову карту арени (`Tilemap`).
  * *Task 1.2:* Підключити Unity New Input System для зчитування напрямку руху (WASD / стрілки).
  * *Task 1.3:* Реалізувати скрипт `SnakeMovement.cs` із дискретним кроком за таймером та захистом від розвороту на 180°.

* **US-02: Збирання їжі та збільшення довжини змійки**
  * *Task 2.1:* Створити префаб `Food.prefab` та скрипти `Food.cs` / `ArenaSpawner.cs` для спавну у вільних координатах сітки.
  * *Task 2.2:* Реалізувати буфер траєкторії (`PathPoint.cs`) і керування сегментами (`SnakeBody.cs`, `SnakeSegment.cs`).
  * *Task 2.3:* Налаштувати додавання нового сегмента (`SegmentPrefab`) при поглинанні яблука.

* **US-03: Завершення забігу та перезапуск**
  * *Task 3.1:* Реалізувати перевірку зіткнення голови з межами арени або координатами сегментів хвоста.
  * *Task 3.2:* Додати відображення поточного рахунку під час забігу.
  * *Task 3.3:* Налаштувати екран `Game Over` та миттєвий перезапуск сцени.

* **US-04: Система roguelite-модифікаторів**
  * *Task 4.1:* Створити структуру даних модифікаторів (`SnakeModifier.cs`, асети в `Assets/Modifiers/`) та менеджер ефектів (`SnakeEffectsManager.cs`).
  * *Task 4.2:* Реалізувати спавн мутагенної їжі (`MutagenFood.cs`), яка ставить гру на паузу та викликає вибір здібності.
  * *Task 4.3:* Зверстати UI-панель вибору (`ModifierCanvas.prefab` + `ModifierSelectionUI.cs`) та підключити застосування обраного модифікатора до змійки.

### 3. Порядок виконання та план першої ітерації (Sprint 1)

Тривалість першої ітерації — **2 тижні**. Послідовність виконання задач визначена технічними залежностями компонентів (від базового руху до надбудови модифікаторів):

| Етап | Задачі | Компоненти / Файли | Очікуваний результат етапу |
| :--- | :--- | :--- | :--- |
| **День 1–6** | Підготовка проєкту, налаштування арени та руху голови змійки | `SampleScene`, `Tilemap`, `SnakeMovement.cs` | Змійка стабільно рухається по клітинках і реагує на клавіатуру |
| **День 7–12** | Реалізація спавну їжі, росту хвоста та траєкторії руху | `Food.cs`, `ArenaSpawner.cs`, `PathPoint.cs`, `SnakeBody.cs`, `SnakeSegment.cs` | Яблука з'являються у вільних клітинках, змійка росте при поїданні |
| **День 13–18** | Обробка колізій, підрахунок поточного рахунку та рестарт | `SnakeMovement.cs`, базовий HUD | Гра коректно фіксує поразку та дозволяє швидко почати новий забіг |
| **День 19–24** | Впровадження системи модифікаторів та UI-панелі вибору | `SnakeModifier.cs`, `SnakeEffectsManager.cs`, `MutagenFood.cs`, `ModifierSelectionUI.cs` | При з'їданні мутагена відкривається панель вибору та застосовується баф/дебаф |
| **День 25–28** | Тестування збірки MVP, виправлення багів і фіксація версії | Усі скрипти та префаби MVP | Стабільний білд першої робочої версії (MVP) |

---

### 4. Висновок
У ході практичної роботи проаналізовано беклог проєкту **Snake-Roguelike** та сформовано межі мінімально життєздатного продукту (MVP). До першої ітерації включено базовий ігровий цикл змійки та систему вибору roguelite-модифікаторів, тоді як збереження глобальних рекордів, додаткові типи порталів/яблук та візуальні ефекти переходів винесено в наступні етапи розробки.
